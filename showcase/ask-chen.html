Least-privilege credentials — no storage key. Remote callers get two scoped queue SAS tokens (expire 2027-10-15): one is add-only on askchen-inbox, the other is process-only (read + delete) on askchen-replies. Neither can read queues, list, or touch anything else — verified: an add-only SAS is 403 AuthorizationPermissionMismatch on a read. Do not share the full connection string (AGENTBUS_AZURE_CONN).

What this is

Ask-Chen is a knowledge-base Q&A agent. You send it a question; a local worker on Chen's machine greps the KB, grounds an answer strictly in the matched evidence, and returns it with sources[], confidence, and a needs_human flag (set when the KB is thin). The wire format is the industry-standard A2A (Agent2Agent v1.0) task model, carried over Azure Storage queues instead of a hosted HTTP endpoint — Azure blocked a public Functions deployment via the MAI-FunctionApps-v010 deny policy, so all compute stays local and queues are the only public door. Any machine with internet + the two SAS tokens can ask.

Flow: client → askchen-inbox (correlation id) → local agentbus worker answers via ask_chen → posts result to askchen-replies (same id) → client polls, deletes its own reply. Questions that need a human are flagged to Chen directly.

Quick start (Copilot / Claude)

For a standalone remote call from any machine, take the two sibling stdlib files from the agentbus repo — azure_client.py + azure_queue.py. Both are pure urllib (no pip install needed anywhere). The Copilot skill's client.py also supports this via --transport remote + env SAS vars.

# remote ask-chen client — stdlib only (urllib), no pip install
copies of:  azure_client.py   +   azure_queue.py          (from Q:\CodeGuru\agentbus)

export AGENTBUS_QUEUE_ENDPOINT="https://askchenagentstor.queue.core.windows.net"
export AGENTBUS_QUEUE_SAS_INBOX="<inbox-SAS: sv=...&sp=a...>"     # askchen-inbox   add only
export AGENTBUS_QUEUE_SAS_REPLIES="<replies-SAS: sv=...&sp=p...>" # askchen-replies read+delete

# over the SAS relay
python azure_client.py --question "What is the MSN ranking funnel?"
# or explicit SAS arguments instead of env
python azure_client.py --question "What is the MSN ranking funnel?" \
  --inbox-sas "sv=...&sp=a..." --replies-sas "sv=...&sp=p..." \
  --endpoint "https://askchenagentstor.queue.core.windows.net"

Output: STATUS: (answered / needs-human) then ANSWER: then SOURCES, CONFIDENCE, NEEDS_HUMAN.

Raw protocol (if you're writing your own client)

  1. Enqueue your question → PUT /askchen-inbox/messages with the SAS (sp=a). Body is XML <QueueMessage><MessageText>{json}</MessageText></QueueMessage> where {json} = {"id":"<corr>","question":"...","caller":"..."}. The corr is a random hex id you generate.
  2. Poll for the answer → GET /askchen-replies/messages?visibilitytimeout=120 with the SAS (sp=p). Each message's text is {"id":"<same corr>","result":{answer,sources,confidence,needs_human}}.
  3. Keep only your own reply. Messages are shared across callers — match on the id, and delete the message you consume via DELETE /askchen-replies/messages/{msgId}?popreceipt={receipt}.
  4. Timeout: the worker usually answers in seconds (retrieval + one router call). Default client timeout 120–180 s is generous. If KB-sensitive questions need Chen, expect needs_human=true (answer may still be present).
SAS service version: the tokens pin sv=2021-02-12. Keep that api-version line in the SAS when sending — the example azure_queue.py uses 2019-12-12 which is accepted, but don't strip or lower the SAS's own fields.

Credentials reference

QueueSAS permissionPermitsDenies
askchen-inbox a (add) Post/Put a question read/list/delete — read returns 403
askchen-replies p (process) read + delete your own reply add/update/list/clear

Both scoped to their own queue only (no account-level access), HTTPS-only, expiry 2027-10-15. To rotate: re-run az storage queue generate-sas (below) and update whoever holds them; the old ones stop working at expiry / on manual rotation.

Owner's references

Rotate / regenerate the SAS tokens

KEY="<AccountKey from agentbus-secrets.json>"
az storage queue generate-sas -n askchen-inbox   --account-name askchenagentstor \
    --account-key "$KEY" --permissions a --expiry 2027-10-15T00:00:00Z --https-only -o tsv
az storage queue generate-sas -n askchen-replies --account-name askchenagentstor \
    --account-key "$KEY" --permissions p --expiry 2027-10-15T00:00:00Z --https-only -o tsv

Run the local relay worker

cd /q/CodeGuru/agentbus
# enable the ask-chen worker + the Azure queue relay (inbox → ask_chen → replies)
AGENTBUS_AZURE_CONN="<conn string>" python server.py --ask-token "$AGENTBUS_ASK_TOKEN" --azure-relay

The worker must be running for remote calls to be answered. It uses the full connection string locally (that's fine — it's Chen's own machine); colleagues never get it.

Local (loopback) same-machine path

If you're on Chen's box, the faster direct path is the A2A HTTP endpoint (no queues): python client.py --transport a2a --question "..." --token "$AGENTBUS_ASK_TOKEN" against http://127.0.0.1:8765. The queue relay exists for the internet-reachable case.
