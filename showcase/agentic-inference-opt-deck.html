The story

An AI-native maturity ladder — L1 → L5

The +28.8% is just the result — the real story is how far along the journey the work has come. The official AI-Native Maturity Model grades that journey in five levels, from AI merely helping out (L1–L2), to AI running the workflow for you (L3), to AI running whole domains on its own (L4–L5).

L1
Assisted
AI helps on discrete tasks — drafting, searching, coding. Human initiates every task.
L2
Embedded
AI embedded in workflows, continuous human supervision; human reviews & approves.
This work sits here
L3
Orchestrated
human sets goals; AI orchestrates workflows, executes multiple steps, iterates; human monitors + handles exceptions.
L4
Autonomous by Domain
AI operates within guardrails — planning, exec, monitoring, error recovery, improvement.
L5
AI Native
products/decisions built around adaptive AI; humans define purpose + policy, not execution.

This agentic work operates at L3 — Orchestrated: goals are human-set, the AI orchestrates the end-to-end workflow, and humans stay on the loop — monitoring progress and handling exceptions. Autonomy grows while judgment stays with people.

Part three

The proof point

The architecture exists to move one number — and to prove the core idea: different layers are optimized collaboratively toward one global optimum, not one-by-one and summed. On a single A100, this won +28.8% — 2045 → 2403 → 2634 output tokens/s.

And the only way it worked is because the agents co-engineered the layers on the agentbus — the system reached a point none of the layers alone could reach.

Takeaways

Summary

  • The idea: optimize different layers collaboratively toward one global optimum — not one-by-one and summed. Summing can hurt; co-engineering on the bus wins.
  • The result: +28.8% on one A100 (2045 → 2403 → 2634), target model unchanged — training-free geometry + trained draft, tuned together.
  • The method: a maturity arc — manual → AI-assisted → AI-consolidated → AI-learning — not a big-bang build.
  • Design the system first: planner · researcher · dev · code review · monitor · devops · eval · judgment.
  • Agents must talk: the agentbus is what makes co-engineering possible — shared state, publish/subscribe.
  • Discipline: evaluation makes evidence gaps visible; human judgment stays in the loop.
From manual research + implementation, to an assistant, to a consolidated workflow, to a learning system — all in service of moving one number on one GPU.
Future work · the step to L4 — Autonomous by Domain

Don't just reuse the expert — learn like him

In-run memory (memory · playbook · cheatsheet) is a cheat-sheet the agent reads. The next step is to internalize it: train the harness on the expert's own past campaigns — successes and failures alike — so judgment lives in the model, not in a note.

1 · Harvest

every past campaign as labeled trajectories — what was tried, what worked, what regressed.

2 · Learn

train / fine-tune the harness on that history, not just read it at run-time.

3 · Act

start each new task from inherited judgment — not from scratch.

4 · Compound

each campaign feeds the next → the system self-evolves run over run.

L4, made concrete — read → internalize → act: this is the difference between a smart assistant (reads notes) and an autonomous operator (has learned the judgment). Humans stay over the loop as governance; the machine carries the why, and the domain expert steers where it goes next.
