Abstract. Content-Agent exposes the decode-throughput workload of the Agentic Inference Optimization program through a trigger / poll / log HTTP surface. It realizes Chen's 7-role autonomous team — one standalone Copilot process per role talking over the agentbus, plus a human Judgment gate. Smoke mode measures baseline and candidate against the same frozen log, giving a reproducible delta 0 and a reviewable no-op diff, so the full loop completes locally. This runbook covers the design, operation, and a risk analysis of migrating the loop to the cloud. Governing principle: the cloud moves compute, never knowledge or credentials — a hybrid control-plane, not a fully-cloud blind agent.

1Architecture trigger · poll · log

Figure 1. Console overview: a thin loopback HTTP daemon wraps the local AgentX loop and exposes trigger/poll/log. The loop runs fully on the local trusted box; a real A100 measurement (non-smoke) is the only step that reaches out to DLIS/AML.

Loopback only. Binds 127.0.0.1:8790 — meant for a browser/script on Chen's box. Not internet-reachable, holds no credentials, no auth. For remote/colleague access use the Ask-Chen runbook (Azure-queue relay) instead.

2Why smoke mode delta 0 · reproducible baseline

Figure 2. Smoke-mode data flow. Without a real A100 log there is no honest local substitute for candidate tps, so both sides measure the frozen baseline — yielding delta 0 and a reviewable no-op diff instead of aborting on "no measured change".

3Helper-role architecture: the co-engine team deck §8 · role split

Figure 3. The co-engine team: the autonomous core runs the loop over the agentbus; Judgment (human) sits at the edge, and Learn / iterate feeds memory into the next round. Each role runs as an independent Copilot process — Planner acts as the true orchestrator (emitting a JSON DAG dispatch plan posted to the AgentBus task board), the 6 downstream roles claim and execute their tasks over AgentBus with Dev as sole writer, and Monitor collects and verifies all 7 deliverables before the interactive Human Judgment Gate.

Target-repo wiring. If launch fails fast with agentx_context_invalid (cause git repository origin lookup failed), the campaign repo lacks remote.origin.url (template uses workspace.mode: clone / git_origin: C:/repos/s2mtp-target). Fix: git -C /c/repos/s2mtp-target config remote.origin.url "C:/repos/s2mtp-target".
Template digest gotcha. Edit only the template source agents/templates/s2-mtp-optimizer/, never the deployed runtime ~/.content-agents/.agent-proxy/.agents/agent_proxy_s2-mtp-loop/. A manual copy into the deployed dir corrupts its recorded digest → instant agentx_template_startup_error (~700ms). Restore from a .rollback-* dir and re-provision (source digest after fixes = 35d1ffad…).

7Cloud rollout — risk analysis move compute; knowledge stays local

Figure 4. Hybrid control-plane: the cloud runs only the single A100 measurement; knowledge, credentials, orchestration, and the human gate stay local. Send compute + the frozen contract out; never the knowledge plane.

Five risk planes. — each collapses into the same root cause:

1 · Data & custodyKB/contract leak · residency · OOM. Worker stays knowledge-blind; ship only frozen contract; pin region; mount not wget.
2 · Identity & accessToken sprawl · wider blast radius. One scoped identity per job; Dev-only writer; fail-closed scopes.
3 · NetworkEgress gates (DLIS/MsftAzVPN) · loopback coupling. Hybrid split; allowlist one endpoint; durable outbox/inbox.
4 · Fidelity & reproducibilityState that doesn't transfer (Q:\ · .pth · podman · PIDs) · env drift. Immutable Dockerfile; pin toolchain + baseline; apples-to-apples TPS delta.
5 · OperabilityObservability distance · cold-start (~1–2h build) · cost hops · lost work. Structured logs, warm pools, batch turns, checkpoint at every gate.
SynthScale network, identity, operability — never the knowledge plane. The A100 bridge (explicit YAML → measure → localize log → real delta) is the right shape.
